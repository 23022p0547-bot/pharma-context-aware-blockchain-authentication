# Context-Aware Blockchain Framework for Pharmaceutical Drug Authentication

Research prototype accompanying the manuscript **“A Context-Aware Blockchain Framework for Pharmaceutical Drug Authentication with Explainable Counterfeit Risk Assessment.”**

The repository implements a permissioned pharmaceutical lifecycle using Hyperledger Fabric, blockchain-linked QR verification, contextual verification logging, and a deterministic explainable risk-assessment layer. It also contains the synthetic datasets, scripts, and result files used for the experimental evaluation reported in the manuscript.

## Research scope

The prototype evaluates blockchain lifecycle integrity, chained provenance, QR-linked record verification, contextual/geospatial evidence, deterministic risk-rule conformance, cross-network verification, and concurrent verification performance. It **does not prove the physical genuineness of a package carrying a copied valid QR identifier** and does not claim real-world counterfeit-detection accuracy from labelled operational counterfeit data.

## Repository structure

- `chaincode/` — Go smart contract and pharmaceutical data model.
- `gateway/` — Node.js Fabric Gateway/Express service connecting the application to the Fabric test network.
- `backend/` — Flask application, contextual verification/risk logic, and benchmark scripts/results.
- `Experiments/` — synthetic lifecycle datasets and scripts/results for 1,000 registrations, 3,000 ownership transfers, and independent provenance validation.

## Main experimental material

The repository includes:

- 1,000 synthetic pharmaceutical product records (`Experiments/products_1000.csv`).
- 3,000 sequential synthetic ownership-transfer records (`Experiments/ownership_transfers_3000.csv`).
- Registration and transfer result files.
- Independent provenance validation (`validate_provenance.py`, `provenance_validation.csv`).
- Controlled risk-rule validation, including the 500-event evaluation.
- Risk-weight sensitivity analysis.
- Component ablation analysis.
- Context-analysis validation.
- Cross-network end-to-end verification results.
- Extended concurrency/scalability benchmark scripts and summaries.

The CSV/XLSX files in this repository are synthetic or experiment-generated research artifacts; they are not patient or clinical records.

## Software prerequisites

The implementation was developed for a Hyperledger Fabric test-network environment with a Go chaincode, Node.js Fabric Gateway, and Python/Flask application. To reproduce the complete blockchain experiments, install and configure:

- Hyperledger Fabric test network compatible with the chaincode/gateway configuration.
- Go (the exact module requirements are recorded in `chaincode/go.mod` and `chaincode/go.sum`).
- Node.js and npm (gateway dependencies are recorded in `gateway/package.json` and `package-lock.json`).
- Python 3 with the packages required by `backend/app.py` and the benchmark scripts (Flask, Flask-Login, Flask-SQLAlchemy, Requests, NumPy, OpenCV, qrcode, user-agents, and analysis dependencies used by individual experiment scripts).

Fabric cryptographic identities and private keys are intentionally **not included**. The gateway expects identities generated by a local Fabric test network.

## Gateway

From `gateway/`:

```bash
npm install
node server.js
```

The supplied gateway configuration expects the Fabric test network relative to the repository and connects to `peer0.org1.example.com` on `localhost:7051`. Review `gateway/server.js` if your Fabric network uses different paths, ports, MSP IDs, channel names, or chaincode names.

## Flask application

From `backend/`, install the required Python packages and run the Flask application according to your local environment. The application expects the gateway at `http://localhost:3000` by default.

For local authentication, `create_users.py` creates demonstration accounts. Passwords should be supplied through the `PHARMACHAIN_*_PASSWORD` environment variables. Placeholder fallback values are for local demonstration only and must not be used in a deployed system.

Set a strong application secret before deployment, for example:

```bash
export PHARMACHAIN_SECRET_KEY='replace-with-a-random-secret'
```

## Reproducing the lifecycle experiment

Start the Fabric network/chaincode and Node gateway before running the lifecycle scripts. The detailed sequence is also recorded in `Experiments/README_RUN_TESTS.txt`.

A small pilot can be run first:

```bash
cd Experiments
python3 bulk_register_1000.py --limit 10
python3 bulk_transfer_3000.py --limit 15
python3 validate_provenance.py --limit 5
```

After resetting the test ledger, the complete lifecycle experiment is:

```bash
python3 bulk_register_1000.py
python3 bulk_transfer_3000.py
python3 validate_provenance.py
```

These scripts use the application's registration/transfer API path so that the lifecycle operations are submitted as Fabric transactions rather than inserted manually into CouchDB.

## Other evaluations

The `backend/` directory contains the scripts used for the controlled risk-rule, context, sensitivity, ablation, cross-network, API, and scalability evaluations. Corresponding CSV outputs are retained so that the reported results can be inspected independently of rerunning the deployment.

## Security and privacy note

This public research package intentionally excludes local databases, Fabric private keys/certificates, `.env` files, generated network identities, runtime credentials, and other deployment secrets. The included application is a research prototype and should not be treated as production pharmaceutical infrastructure.

## QR cloning limitation

A copied QR identifier from a genuine package can still resolve to a legitimate blockchain record. The current prototype therefore uses repeated scans, scan frequency, temporal/contextual evidence, and approximate geospatial evidence as indicators of suspicious identifier reuse. It does not implement a physical anti-cloning mechanism or establish which physical package is genuine when the same valid identifier is copied.
